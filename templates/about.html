BTech Data Science Final-Year Capstone Project

Blockchain-Integrated Multimodal Biometric Electronic Voting System

A tamper-evident, decentralized electronic voting architecture engineered with OpenCV computer vision, multimodal biometric fusion, ECDSA digital signatures, and SHA-256 linked blockchain consensus.

Project Objectives

  • Decentralized Tamper-Resistance: Store immutable vote transactions on a Proof-of-Work blockchain that makes vote manipulation mathematically detectable.
  • Multimodal Biometric Authentication: Eliminate voter impersonation by requiring simultaneous validation of fingerprint minutiae and facial geometry using OpenCV.
  • Ballot Secrecy & Privacy: Decouple voter identity from the ballot choice using anonymized voter authorization token hashes H(voter_id + salt).
  • Cryptographic Non-Repudiation: Generate ECDSA SECP256K1 digital signatures for every cast ballot.
  • Prevention of Duplicate Voting: Enforce strict single-vote authorization checks at both application and consensus layers.

Mathematical Models & Security Specifications

1. SHA-256 Avalanche Effect

Every block header is cryptographically bound:

Hash = SHA256(Index + PrevHash + TxRoot + Nonce)

Changing a single bit in a recorded transaction produces an entirely uncorrelated 256-bit hash, breaking the entire downstream chain.

2. Cosine Similarity (Facial Scan)

L2-normalized spatial Local Binary Pattern feature embeddings are compared via dot product:

Sim(A, B) = (A • B) / (||A|| • ||B||)

A score ≥ 0.65 confirms facial identity against enrolled templates with illumination invariance.

3. ECDSA Digital Signatures

Elliptic Curve Digital Signature Algorithm over SECP256K1 curve:

Sig = ECDSA_Sign(PrivKey, SHA256(TxPayload))

Guarantees that only the voter's private key could have originated the ballot transaction, providing non-repudiation.

Cloud Deployment & Academic Architecture Considerations

Hardware Biometrics vs. Cloud Boundaries

Physical USB optical scanners (e.g., DigitalPersona, SecuGen) require local device drivers and cannot be addressed directly across remote serverless cloud environments due to browser hardware isolation boundaries. For this reason, the application features an integrated Biometric Demo Mode that mathematically synthesizes high-contrast sinusoidal fingerprint ridge patterns and normalized face embeddings, as well as browser-level webcam and image upload support.

Serverless Ephemeral Storage

Serverless platforms like Vercel execute inside ephemeral, read-only containers with a temporary /tmp scratchpad. In cloud deployments, the SQLite database resides in /tmp/voting.db and is auto-seeded on cold starts. For persistent enterprise production, the architecture seamlessly supports external cloud databases (e.g., Neon Postgres, Supabase) and public Ethereum/Polygon smart contracts.

Future Ethereum & Smart Contract Extensibility

The project architecture is deliberately decoupled into modular components. The simulated Python blockchain implements standard Ethereum JSON-RPC compatible payloads (to_ethereum_payload()), enabling seamless migration to Ethereum Mainnet, Polygon, or private Hyperledger Besu networks via Solidity smart contracts:
